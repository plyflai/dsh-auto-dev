# 交付切分

在需求涉及多项结果、依赖或交接时使用。简单任务可以没有计划。

选择能独立验收的用户结果作为切分单位。让一个单元贯穿必要层；存在实际依赖再表达 DAG。分组用于导航，只有叶子表示待做工作，容器不能增加完成数。

检验一步拆得对不对，只问一句：如果只做到这一步就停下，能验证它是对的吗？能，就合理；不能，就重拆。

- 好的切法：「用户能用一个关键词搜到笔记」→「搜不到时给出明确提示」。每步都有人看得见的结果。
- 坏的切法：先定义类型和接口 → 再写前半段逻辑 → 再补剩下的 → 最后统一测试。按技术层横着切，前几步都无法单独验证。

每个需要计划的叶子说明目标、范围和验收；界面声明与风险相称的 `ui` 档位。不要为了调用工具把本可一次完成的修改拆成登记步骤。

有阶段结果就说明结果与下一动作。`partial` 继续已授权工作；剩余叶子、任务验收和真实等待决定是否收尾。范围缩减必须来自明确决定，不能通过删除未完成叶子伪造完成。

交付时给可使用产物、验证结果和具体限制。人工验收任务交到 `review_ready` 后等待真实用户决定；自动验收任务满足既有验收后收尾。
