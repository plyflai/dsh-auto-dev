# 行为场景

在业务规则、条件分支或多人理解容易偏离时，把用户语言变成可验证行为。

一个场景描述：前置条件 → 一个动作 → 可观察结果。选择正常路径、实际边界与已观察失败；不要给每次小改动机械补齐场景模板。

例如：任务含一个 done 和一个 blocked 叶子 → 提交已完成叶子 → 任务保持未完成，面板显示 blocked。场景应检验状态和用户可见结果，而不只检验函数被调用。

优先复用项目已有场景跑台和夹具。需要回归时保留能暴露缺陷的断言；无法运行时说明条件，不把文档中的场景当作已经执行。

业务规则不确定时提出关键问题或标明假设。`record` 保存结论是可选动作，不能替代用户选择或自动升级授权。
