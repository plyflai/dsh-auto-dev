# 影响分析

在修改已有代码、移动接口或重构时使用。目标是找到最小完整改动面。

## 动作

从请求对应入口查符号、调用方、状态 owner、数据契约与测试。代码调用方用 codegraph 的 `blast_radius` 查；用之前先让索引跟上源码：`codegraph status` 找不到索引就 `codegraph init -y`，有索引就 `codegraph sync`（增量，秒级）。codegraph 是必需前提：命令不存在、建索引失败或这类语言不支持时，不要退回手搜，把原始报错原样告诉用户，停下等用户裁决。

codegraph 只看代码符号。被改的路径、配置键、字段名还要用 `rg` 搜一遍文档、配置、模板和 JSON。

## 调用图看不到的依赖

下面几类不会出现在调用方列表里，改动碰到它们时逐条搜：

| 类型 | 例子 | 怎么查 |
| --- | --- | --- |
| 解析字符串 | 用正则从文案里抠价格里的 `$`、从文件名里取日期 | 搜引用这段文本格式的正则和 `split` |
| 依赖顺序 | 默认列表已排好序、第一个元素就是最新的 | 看排序与遍历的地方 |
| 依赖时序 | 默认 A 一定在 B 之前完成、回调一定先到 | 看异步、并发、事件监听 |
| 依赖缓存 | 默认缓存里已经有这条数据 | 看缓存的读写点和失效时机 |

另外三个方向：数据流（这个值从哪来、写到哪、谁再读它）、配置（开关、环境变量、默认值）、运行环境（版本、平台、部署差异）。

## 决定改动

比较现有可复用实现、依赖与兼容约束，再决定改动。修改字段或返回结构时，连同调用方、持久化、投影和 UI 一起核对；仅格式调整无需扩展为架构调查。

## 产出

用简短说明列出实际受影响入口、必须保留的行为与验证方法。新文件或新依赖本身不构成停工理由；先判断现有模块是否更适合。

授权范围内可逆的实现选择自主处理。只有实际范围、权限、不可逆边界变化或 codegraph 不可用才需要用户决定。不要为假设风险新增镜像库、冻结或门禁。
