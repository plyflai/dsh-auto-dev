# 测试

在补测试、做覆盖、写回归用例时使用。目标是测试能抓住真 bug，换个写法不误报。

## 动作

1. 先看项目现有测试怎么放、怎么写、用什么命令跑，照着来；不引入新测试框架。
2. 测外部看得见的行为：输入→输出、退出码、写出的文件、抛出的错误。不断言内部调用了哪个函数、调了几次。
3. 每个功能至少一个失败或边界用例：空输入、不存在的 id、重复数据、边界值。
4. 修 bug 时先把原来的失败场景写成测试，跑一次看它红；修完再跑看它绿。写不出能红的测试，就在交付里说明。
5. 用项目的测试命令跑全量，不只跑新文件。

## 产出

说明新增了哪些行为的测试、哪个是失败/边界用例、全量跑的结果。没覆盖到的写出来。
