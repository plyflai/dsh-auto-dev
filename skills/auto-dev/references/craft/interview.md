# 需求访谈

零散要求先理成「目标 + 几条验收」，在回复里对用户复述一遍；看到更省事或更对的做法，直接讲清两种做法的差别，等用户选。不需要调用任何工具或填写记录。

只在歧义会改变实现、验收或授权边界时提问。先查已有请求与项目知识。

找出一个最影响下一动作的问题。用用户能判断的结果表达选项，说明默认假设与影响。能在明确、可逆假设下继续时，说清假设并继续独立工作。

真正需要用户决定且无法继续的选择才等待。把具体问题或方案展示给用户；记录字段不能代替实际提问。已有答案或已声明继续假设时，不制造待答状态。

涉及业务规则时保留真实来源和上下文。模型提出的推断不能写成用户已经确认。只保存影响后续实现的结论；不要求固定问题数量或开工前访谈仪式。
