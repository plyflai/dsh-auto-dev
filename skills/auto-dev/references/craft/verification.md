# 验证

在需要判断“是否做完、是否通过”时使用。验证深度由改动影响与验收决定。

## 动作

1. 把验收改写成可观察结果，选择能推翻错误实现的检查。
2. 运行项目已有的最小有效检查；失败后按输出修复，再复测受影响路径。
3. 若改动跨边界，再验证实际边界：构建产物、服务请求、浏览器交互或隔离运行。
4. 用真实命令、输出及当前文件版本关联结果。改写文件后，旧检查不能证明新版本。

改动碰到下面任何一项，单元测试不够，要跑一次贯穿真实链路的检查（端到端、真实请求或浏览器）：认证、支付、权限、审批、上传下载；多步表单、多页面跳转、会话状态、核心用户链路；外部系统联动；API 或数据格式变更；跨模块改动。

单纯格式或可逆文案改动不要求新测试。测试不能只复述实现。需要回归时，覆盖触发条件和用户可见结果；可稳定复现的缺陷先保留失败证据。无法构造自动复现时，写清实际观察与未验证部分。

## 产出

说明结果、检查范围、仍未验证项。`work_submit` 的 claim 指向实际 `callId`；成功状态必须来自成功执行，不能用打印的命令、吞失败包装或旧日志替代。

声明 `ui` 档位的单元仍须满足该档或更高档。没有浏览器证据就不宣称已完成真实浏览器验收。验证失败用于继续定位；只有实际权限、人工决定或外部前提缺失才等待用户。
