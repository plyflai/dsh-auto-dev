# 重构

在重构、提取、改名、拆文件，或用户说「行为不变、只改结构」时使用。目标是结构变了，外面看不出任何区别。

## 动手前

先用[影响分析](impact.md)找全调用方，再定一个改动前的基线：项目检查跑一次绿；没有覆盖到要动的行为，先补一条测当前行为的测试，看它绿。基线不绿就不是重构的起点，先说明。

## 一小步一检查

每一步都能单独停下：改名、挪位置、提取各算一步，每步之后跑项目检查。不在同一步里顺手修 bug 或加功能；发现了，记下来，交付时单列。

删旧名之前，确认没有调用方还在用：代码、配置、文档、模板、对外接口都搜一遍。

## 怎么证明行为没变

逐条核对：

1. 同样的输入，输出、走的分支、产生的副作用都一样；
2. 原来的调用方式还都能用；
3. 没有多出写库、请求、文件或状态变化。

能用测试证明的用测试；测不到的（对外接口、导出名、命令行参数），对比改动前后的实际结果。

## 产出

交付时说：哪些结构变了、哪些行为没变、各用什么核对的；碰到但没顺手改的问题单列。
