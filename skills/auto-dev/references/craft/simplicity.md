# 实现取舍

在动手写、改或删代码之前使用。目标是用最少的改动实现请求，并且不碰到相邻内容。

## 保留优先

用户说添加，就在原有内容上添加，不要替换；说修改，就改要改的那几处，不要整段重写；说删除，只删明确点名的目标。顺手的重排、改名和格式化不在请求里，就不做；它们会把真正的改动淹没在 diff 里。

改动范围超出请求时，先说明为什么必须改，再动手。

## 先选更轻的做法

按顺序考虑：不做也能满足 → 复用已有实现 → 用语言或框架自带能力 → 用已有依赖 → 写局部代码。前一个可行，就不走后一个。新依赖、新抽象层、新配置项都需要当前请求里的理由，"以后可能用到"不算理由。

## 抽象纪律

同样的代码出现一两次，保持重复；出现第三次，再看它们是否真的因为同一个原因变化，是才抽出来。一个文件或函数同时承担多件事、改一处要读懂全部时，先拆开再加功能。

## 产出

diff 只包含请求需要的行。偏离以上做法时（整体重写、加依赖、新抽象），在阶段结果里写一句原因。
